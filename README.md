# 🏐 ScoreLayer Volley

A mobile-first volleyball score tracker with timestamped point logging, multi-format export for Final Cut Pro / iMovie / YouTube, and **Live Share** so parents in the bleachers can see the live score and submit highlights straight from their phones.

## Features

- **Live scoring** — Tap + / − to track points with set/match auto-detection
- **Sync button** — Press at a known video moment (first serve or recording start) to align timestamps; available right on the setup screen so you can start the recording and sync *before* typing team names
- **Editable team names anywhere** — Fix a typo from the setup screen, mid-match (mirrored live to spectators), or on the match-complete screen
- **Live Share** — Publish the match to spectators via a QR code or a link you can paste in a WhatsApp group; parents see real-time scores and submit highlights from the stands
- **YouTube chapters** — Auto-generate a chapters file with set boundaries and highlight markers
- **In-browser MP4 overlay** — WebCodecs generates a chroma-keyable scoreboard video right in your phone; merge it with your recording in iMovie (iPhone/Mac) or any equivalent app on Windows
- **SRT export** — Import directly into Final Cut Pro or YouTube as captions
- **FCPXML export** — Native Final Cut Pro timeline with positioned title clips
- **ASS export** — Advanced SubStation Alpha subtitles with positioned score + info rows
- **CSV export** — Full point log with wall-clock time, video offset, set/match state
- **Chroma Key Kit** — ZIP with Python + FFmpeg fallback for desktop overlay generation
- **PWA** — Add to Home Screen on iPhone/iPad for a native-app experience

## Usage

1. Open the app URL in Safari
2. Enter team names and tap **Start Match** — or, if you're in a hurry, press **Sync** first and fill in the names later
3. Press **Sync** when the video recording starts (or at first serve) — from the setup screen or the match screen
4. Tap **+** for each point scored, **★** to mark a highlight
5. When the match ends, export in your preferred format

## Live Share

With Firebase configured, a scorekeeper can publish the match live so spectators see the scoreboard update on their phones in real time.

**Three roles** (`state.role`):

- **`solo`** — default. No network writes. Identical to pre-v3 behavior.
- **`scorekeeper`** — created by tapping **Share live** in the MATCH header. Writes scores, highlights, and metadata to Firebase RTDB.
- **`spectator`** — entered automatically when the URL contains `?m={matchId}`. Read-only scoreboard plus a one-tap highlight submission form.

**Spectator URL format:** `https://<host>/scorelayer-volley/?m={matchId}` — generated by the Share modal as a QR code that parents scan.

**Parent highlights:** spectators can submit highlights with an optional note (140 chars), name (40 chars), and tag chip (ace / block / kill / dig / set / error). One-tap submission is supported via the `★ Quick` button. The scorekeeper sees an in-app moderation panel and can hide individual entries.

**Where parent highlights appear in exports:** YouTube chapters, CSV, Highlights SRT, **and** the in-video score overlay all merge accepted (non-deleted) parent submissions alongside the scorekeeper's own `★` highlights. Each parent highlight flips the `★` on the overlay entry whose timestamp it falls inside, and appends `[tag · name · note]` to that entry's highlight note.

**Score snapshot:** the live score is frozen at submission time, so the in-video overlay and the spectator feed can show "S2 14–12" even if the scorekeeper corrects the score later.

## Firebase Setup

Live Share is optional. With an empty `databaseURL` the Share UI auto-hides and the app behaves identically to solo.

To enable it:

1. Create a Firebase project on the Spark (free) tier.
2. Enable **Anonymous Auth** under Authentication → Sign-in method.
3. Enable **Realtime Database** and pick a region.
4. Open `index.html` and paste your project's web config into the `FIREBASE_CONFIG` object near the top of the script block.
5. Open **Realtime Database → Rules** in the Firebase console and paste the contents of [`firebase-rules.json`](./firebase-rules.json). These rules restrict `meta/` and `points/` writes to the scorekeeper UID, cap parent notes at 140 chars and names at 40, and only let the scorekeeper flip an entry's `deleted` flag.

**RTDB tree** (`/matches/{matchId}`):

- `meta/` — scorekeeper-only writes: teamA, teamB, syncTimestamp, scoreboard mirror, `scorekeeperUid`
- `points/` — append-only point log; same shape as the local entries (corrections are written as new entries with `correction:true`)
- `parentHighlights/{pushId}` — any signed-in user appends `{ name?, note?, tag?, quick, snapshot?, clientTimestamp, serverTimestamp, deleted }`

## Deployment

Push to `main` — GitHub Actions (`.github/workflows/deploy.yml`) auto-deploys the repo root to GitHub Pages. There is no build step.

To deploy your own:

1. Fork this repo
2. Go to **Settings → Pages → Source**: select "GitHub Actions"
3. Push to `main` — the site deploys automatically

To preview locally, serve the root directory with any static file server:

```bash
python3 -m http.server 8080
```

> **Beta-era share links:** `index-v3.html` exists at the repo root as a thin redirect to `index.html` (preserving any `?m=` query string), so QR codes generated during the v3.0 beta keep working.

## Tests

Tier-1 unit tests guard the export pipeline (YouTube chapters, CSV, SRT, FCPXML, ASS, Highlights SRT) against regression. They live in `tests/` and run on Node 20+ built-ins only — no `package.json`, no install step, no toolchain.

```bash
node --test tests/*.test.mjs
```

The harness (`tests/harness.mjs`) reads `index.html`, slices the region between the `// EXPORTERS_BEGIN` and `// EXPORTERS_END` sentinel comments, and evaluates it in a `vm` context with stubbed `window`/`document`/`localStorage`/`firebase`. Exported pure functions are then imported into `tests/exports.test.mjs`. Fixtures live under `tests/fixtures/`. CI runs the suite on every PR via `.github/workflows/test.yml`.

## Analytics

ScoreLayer Volley uses two privacy-first, cookieless analytics tiers. No consent banner is required — no cookies, no fingerprinting, no personal data collected.

| Tier | Tool | Purpose |
|---|---|---|
| Pageviews & traffic | Cloudflare Web Analytics | Visits, referrers (Instagram), devices |
| In-app events | Matomo (self-hosted, cookieless) | Feature adoption, export usage, match completion |

**Tracked events:** `Match.Start`, `Match.Complete`, `Match.EndEarly`, `Highlight.Mark`, `Export.SRT/FCPXML/ASS/CSV/ChromaKit/Chapters/HlSRT`, `Export.MP4Start`, `Export.MP4Success`

## Tech Stack

Single `index.html` file — React 18 + Babel Standalone (CDN), `mp4-muxer` ES module for WebCodecs MP4 generation, Firebase Realtime Database + Anonymous Auth for Live Share. No build step, no npm, no backend beyond Firebase.
